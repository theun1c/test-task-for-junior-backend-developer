# DECISIONS.md

## 2026-04-23

- Настройки периодичности храним в колонке `tasks.periodicity_settings` типа `JSONB`.
- В Go используем typed-модель `task.PeriodicitySettings`, а не `map[string]any`.
- `nil` в `PeriodicitySettings` означает обычную непериодическую задачу.
- Периодическая задача хранится одной записью в `tasks`; новые записи задач по расписанию не создаются.
- Для периодической задачи в `tasks` храним календарный интервал действия и правило выбора дат.
- Состояние завершения конкретной даты храним в отдельной технической таблице, а не в JSON задачи и не в виде дублирующих записей `tasks`.
- Режим "на конкретные даты" интерпретируем как список конкретных даты и времени.
- В доменной модели такие значения храним как `[]time.Time`.
- Во входных данных HTTP API дата и время передаются в формате `dd.mm.yyyy hh:mm`, например `25.03.2026 10:10`.
- Общее состояние записи задачи храним в поле `tasks.state` со значениями `active`, `paused`, `archived`.
- В календарной выборке участвуют только задачи со значением `state = active`.
- Обычная задача без `periodicity_settings` может участвовать в календаре как разовое событие по полю `schedule_start_at`.
- Для календарной выборки обычной задачи требуется точное совпадение выбранных даты и времени с `schedule_start_at` до минуты.
- Для периодических задач завершение конкретной даты хранится отдельно от общего поля `tasks.state`, чтобы не смешивать состояние записи и состояние календарного вхождения.
- Повторное завершение одного и того же календарного вхождения считается конфликтом и должно возвращать ошибку, а не тихо игнорироваться.
